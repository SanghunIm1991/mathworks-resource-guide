## 詳細解説

MathWorksの新しい機能には、ドキュメントが英語しかないものや、読むのに理数工の前提知識（微分方程式・線形代数・機械学習等）が要るものがある。そうした機能について、前提知識から順に説明する解説を`guides/`に置く。リンク集が「どこを読めばよいか」を示すのに対し、解説は「読んで分かるための中身」を、先頭から順に読む教科書として書く。

### 1冊の解説の書式

解説は、関連するテーマの番号に`a`・`b`…を付けて、`guides/<テーマの番号><a,b,…>-<英語の短い名前>.md`に作る（例: `guides/03a-neural-state-space-model.md`）。関連するテーマのファイルの冒頭にも、解説へのリンクを書く。

1. **見出しと確認日**: 関連するテーマ、確認日、調査時点の最新リリース、元のドキュメントの言語を箇条書きで書く。続けて、何を学ぶか、なぜこの解説が要るかを短い文章で書く。
2. **想定環境・前提・所要の目安**: 必要な製品とリリース、前提の知識、前提の文書（先に読むテーマ等）。
3. **注記**: 「期待する結果」の出どころ（作成時にMATLABで実行していないこと）、コードが例題の丸写しでないこと。
4. **0. 学習目標と完了条件**: 読み終えるとできるようになることを番号付きで書く。
5. **1. 全体像**: mermaidの図で流れを示す。
6. **本文の節**: 前提知識 → 機能のしくみ → MATLABでの手順（コードと「期待する結果」と読み方） → 使い方。初出の用語にはその場で1文の定義を置く。公式の記述と、解説の著者の整理・一般論は書き分ける。
7. **確かめの問い**: 答えを`<details>`に書く（空欄の表は置かない）。
8. **次に読むもの・出典**: 参照した公式のページ（言語・確認日）と、逐語の転載でない旨。

URLの書き方と確認の手順は、リンク集と同じ（下の「URLの書き方」「調べる手順」）。

## 情報源の範囲

- MathWorksのドメイン（`mathworks.com`とそのサブドメイン。`jp.mathworks.com`・`blogs.mathworks.com`等）のページ。ドキュメント・製品ページ・ブログ・ビデオ・講演資料・ウェビナー資料を含む。
- YouTubeの公式チャンネル「MATLAB」（`@MATLAB`）と「MATLAB Japan」。
- MATLAB Answers等のコミュニティの回答は、MathWorksの社員以外の回答も含むため、載せる場合はその旨を書き添える。
- 第三者のブログ等は載せない。どの情報源も、文章を転載せず、リンクと自分の言葉での要約だけを載せる。

## 1テーマのファイルの書式

テーマごとに`themes/NN-<英語の短い名前>.md`を1ファイル作る。

1. **見出しと確認日**: テーマ名の下に、次の3項目を箇条書きで書く。
   - 確認日（調査した日付）
   - 調査時点の最新リリース
   - 日本語版のページの表示（日本語版は英語版より更新が遅れることがあるため、表示されていたリリース。確認していなければその旨）
   - 詳細解説（「[詳細解説](#詳細解説)」の節の解説がある場合だけ、そのファイルへのリンク）
2. **概要**: 次の3つを小見出しで分けて書く。
   - はじめに: そのテーマが必要になる場面、基本の考え方、初めて出る用語の説明を、文章で書く。最後に、入門の内容を【1】【2】…の項目に分けて示す。
   - 入門の内容とリンクの関連図: 行を入門の項目、列を用途（下の「用途の分類」）にして、そのファイルのすべてのリンクの題名を配置した図（`themes/img/NN-relation-map.svg`）。リンクを足したら図も作り直す。
   - 何ができるか、主な関数・アプリ・ブロック、必要な製品（ツールボックス）。小見出しの名前は内容に合わせる（例: 「主な関数と製品」「方法の整理」）。量が多ければさらに小見出しで分けてよい。
3. **読む順番の目安**: 初めて調べる人がどこから読めばよいか。
4. **リンク**: 種類ごとの表に分ける。種類は次のとおりで、該当がない種類は省く。
   - ドキュメント（量が多ければ「ドキュメント（ブロックの操作）」「ドキュメント（用語の解説）」のように用途ごとの小見出しに分けてよい。`/discovery/`の用語の解説のページは、ドキュメントの中に入れる）
   - 製品・ソリューションのページ
   - ブログ
   - 講演資料（PDF）
   - 動画（`/videos/`のウェビナーの録画もここに入れる）
   - コミュニティ（MATLAB Answers等。MathWorksの社員以外の回答も含む旨を書く）

   各行に次を書く。
   - リンク（ページの題名）
   - 用途（学習の段階での使い方。下の「用途の分類」のどれか1つ）
   - 一言の説明
   - 必要な製品と対応リリース（分かる場合。「R2018a以降」等）。列挙しきれない場合は主なものを書いて「ほか」を付け、製品を特定できないページ（用語の解説等）は「—」とする
5. **補足**: 注意点（古い情報、名前の変わった機能等）、見つからなかったもの。

### 用途の分類

リンクの表の「用途」の列は、学ぶ順番に沿って次の4つに分ける。初めて調べるときは、概要→チュートリアル→サンプルの順にたどり、辞書は必要になったときに引く。1つのページが複数に当てはまる場合は、主な使い方の1つを選ぶ。

| 用途 | 使い方 | 当てはまるもの |
|---|---|---|
| 概要 | 何ができるか、どれを使えばよいかをつかむ | 用語の解説、製品・ソリューションのページ、手法の分類や使い分けの解説、紹介の動画・講演 |
| チュートリアル | 手順を追って学ぶ | 入門のページ、作業の流れの解説、操作手順を示すブログ・動画 |
| サンプル | 具体例を読んだり、真似して動かしたりする | ドキュメントの例題、実例を示すブログ |
| 辞書 | 必要なときに引いて調べる | 関数・ブロック・アプリのリファレンス、カテゴリのページ（関数・例題の一覧）、特定の関数の注意点 |

## URLの書き方

- 検索結果やページの取得で実在を確かめたURLだけを載せる。推測で組み立てたURLは載せない。
- ドキュメントは`jp.mathworks.com`で載せる（日本語版がない場合も日本語サイト上の英語版が開く）。`jp.`版の実在も確かめる。
- 国別のサブドメイン（`in.`・`se.`・`kr.`等）は使わない。製品ページ等で`jp.`版がないもの、動画のページ（`/videos/`）、講演資料のPDFは`www.mathworks.com`で載せる。
- 検索で見つかっても、`www.`・`jp.`のどちらも404になるページ（移動・統合されたもの）は載せず、テーマの「補足」に書く。
- 末尾の`_ja_JP.html`等の言語別ファイル名や、検索の追跡用のクエリ文字列は取り除く。
- YouTubeは`https://www.youtube.com/watch?v=<ID>`の形にそろえる。

## 調べる手順

1. **ドキュメント**: テーマの関数名・機能名（英語と日本語）で、`mathworks.com`にドメインを絞ってWeb検索する。カテゴリのページ（関数の一覧）と、入門のページ（例題つきの説明）を起点にする。
2. **ブログ**: `blogs.mathworks.com`に絞って検索する（英語の「Guy on Simulink」等、日本語の「MATLAB ユーザーコミュニティー」等）。
3. **講演資料・ウェビナー**: 「MATLAB EXPO」に限らず、テーマのキーワード（日本語・英語）で`mathworks.com`内を検索する。新しい年の資料は検索で見つかりにくいので、MathWorksの「[イベントの講演資料を検索](https://jp.mathworks.com/company/events/conferences/search-proceedings.html)」のページも使う。見つからなければ「補足」にその旨を書く。
4. **動画**: `youtube.com`と`mathworks.com/videos`に絞って検索する。YouTubeの動画は、oEmbed（`https://www.youtube.com/oembed?url=<動画のURL>&format=json`）の`author_name`で公式チャンネル（「MATLAB」「MATLAB Japan」）の投稿かを確かめる。動画の中身は確認できないので、題名と説明文から判断する。
5. **確認**: 載せるURLの実在（`jp.`版を含む）を確かめ、確認日を書く。`mathworks.com`はボット対策のため`curl`等の単純な要求を拒む（HEADは405、GETは403）ので、Claude CodeのWebFetchでページを取得し、題名・言語・導入リリース（「R2018a で導入」等）を読み取って確かめる。
